# STM32C5 notes — read before writing any STM32 module

Both STM32 boards (control and lane) use the STM32C542 with the new modular
C5 HAL generated by CubeMX2. These are the traps and facts found so far, so
nobody has to rediscover them. Each line names where it was found. Add to
this file whenever you hit a new one.

## HAL behaviour

- **`HAL_OK` is `0xEAEAEAEA`, not 0.** Always compare `== HAL_OK`. Host-test
  shims must use the real value. (hub, both trees' `*_status.h`)
- **Timers trap on double start/stop.** Starting a running channel or
  stopping an idle one asserts. Flip your state flag only after the HAL call
  succeeded, and finish a half-done switch instead of retrying it.
  (`indicator_led.c` in both trees)
- **Advanced timers (TIM1/TIM8):** `HAL_TIM_OC_StartChannel()` sets MOE; the
  stop clears it once no channel is left. Nothing extra needed. (lane guide §9)
- **Re-armable alarms from an ISR:** use LL register access, not the HAL
  channel state machine. (lane `lane_timer.c`)
- **I3C controller: `HAL_I3C_PRIVATE_WITH_ARB_RESTART` is defined as STOP
  alone** (HAL bug). `i3c_ctrl.c` builds its own control words for private
  transfers with a repeated start. (control, 2026-11-17)
- **I3C controller: 4 device slots** (`DEVRx`, HAL index 0..3). An IBI from
  a target not in a slot is NACKed. With 6 lanes, v1 polls instead of using
  IBI. (control guide §10 Q1)
- **I3C controller hot-join flow:** HJACK + HJ notification →
  `DynAddrAssign_IT(ONLY_ENTDAA)` → each target's payload in
  `TgtReqDynAddrCallback`, answered with `SetDynAddr` → `DAACpltCallback`.
  (control guide §10 Q2)
- **I3C early read end works:** the target stops after its preload count
  (TGTTDCNT); the controller reports SR.ABT and the real length in SR.XDCNT.
  (control guide §10 Q3)
- **I3C target HAL does one fixed-size transfer at a time,** which cannot
  serve a register-pointer model. The lane installs its own ISR in the
  handle's `p_isr_func` and drives the FIFOs with LL. (lane `lane_bus.c`)
- **CubeMX2 USB:** the generated `mx_usb_drd_fs.c` also defines the IRQ
  handler for the HAL PCD driver. With TinyUSB, exclude that file in CMake
  and supply `mx_usb_drd_fs_device_init()` yourself. (control `usb_cdc.c`)

- **CRC unit as CRC-32 (IEEE):** POLYSIZE 32, POL 0x04C11DB7, REV_IN byte,
  REV_OUT bit, 8-bit writes, INIT = rbit32(state) before each chunk, final
  XOR in software (the unit has none). The generated `mx_crc.c` only sets
  poly/init defaults (no reversal): set the rest after `mx_crc_init()`.
  Word writes would need REV_IN = word, so byte writes are used. Control
  `crc32.c` (hardware on any ARM build, software on host, `-DCRC32_SOFTWARE`
  forces software); lane `image_crc.c` (LL registers; **the lane CubeMX
  project has no CRC block, and `stm32_hal.h` there does not pull in the LL
  CRC header, so it includes `stm32c5xx_ll_crc.h` itself and enables the AHB1
  clock with LL. CubeMX change, optional: add CRC to the lane project**).
  Host tests check a bit-exact model of the register semantics against the
  software path. The CRC-16 in `frame_codec.c` stays software: the file is
  shared byte-identically with the nRF build and the host tests.
- **RNG (reviewed 2026-11-18):** `HAL_RNG_RecoverSeedError()` asserts unless
  the HAL state is ERROR, which only a HAL_ERROR (seed error) leaves; a
  HAL_TIMEOUT returns to IDLE. `rng.c` now recovers only after HAL_ERROR and
  retries once; the timeout is 10 ms (1 ms tick granularity made 2 ms fragile).
  The Yuhka hub's fixed `mx_rng.c` additionally calls
  `HAL_RNG_EnableAutoReset()` and `HAL_RNG_EnableClockErrorDetection()` after
  the NIST config; ours does not, so `rngInit()` calls both. Clock: hub uses
  CK48 = HSIDIV3 (C531, no USB); control keeps PSIDIV3, which `mx_rcc.c`
  already enables for USB, so that is correct here. **CubeMX change:** enable
  auto-reset and clock error detection in the RNG config so `mx_rng.c`
  matches the hub, then drop the two calls in `rng.c`.

## Chip facts

- **Flash:** 8 KB erase pages, 128-bit (quad-word) programming, about 2.1 ms
  per page erase. Bank 2 is read-while-write against bank 1, so settings in
  bank 2 can be written while code runs from bank 1. Flash ECC errors raise
  an NMI. (control `flash_drv.c`, `fault_guard.c`)
- **TRNG** exists on the C542. (control `rng.c`)
- **WKUP pins shadow GPIO:** an armed WKUP pin breaks the GPIO/EXTI read of
  that pin. The generated `mx_pwr_init()` arms WKUP1 at boot: disarm it at
  init, arm only at Standby entry. (hub `sys_power.c`, lane guide §8.1)
- **TIM12 stops in Stop1,** and with it the control module's system clock:
  the control module only ever uses WFI. (control `sys_time.h`)
- **ROM bootloader:** USART1 on PA9/PA10 and USB DFU; no I²C/I3C. Empty flash
  falls into it. (HARDWARE_REFERENCE §6)
- **Option bytes:** BOOT_SEL decides whether the BOOT0 *pin* is honoured.
  The C5 LL/HAL and the hub's script disagree about its polarity: check on
  the bench (control BENCH_TESTS F-4) before writing it. Never copy the C542
  hub's BOOT_SEL setting: our boards have a real BOOT0 pull-down.
- **PB4 / PA15** come out of reset with JTAG pull-ups (NJTRST / JTDI).
  (HARDWARE_REFERENCE §2.7)
- **`sysTimeNowUs()` must not be called from a priority-0 ISR** (UIF race).
  (control `sys_time.h`)

## CubeMX2 workflow

- A GUI *Generate* rewrites the root `CMakeLists.txt` (re-add the one
  `include(cmake/<tree>_app.cmake)` line) and may rewrite
  `CMakePresets.json` (hand-added presets are lost). Diff both afterwards.
- Safer: generate into a scratch folder and copy only the changed
  `generated/` files (control notes, "CubeMX pass 2026-11-17").
- Toolchain: `~/.local/share/stm32cube/bundles/{cmake,ninja,gnu-tools-for-stm32}/<ver>/bin`.
